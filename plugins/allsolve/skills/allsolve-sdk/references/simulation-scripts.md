# Allsolve simulation scripts

**Contents:** [Attach custom code](#attach-custom-code) · [Solver environment vs SDK script](#solver-environment-vs-sdk-script) · [Inspect generated scripts (reference only)](#inspect-generated-scripts-reference-only) · [Typed stubs (Script API)](#typed-stubs-script-api) · [Troubleshooting (logs only)](#troubleshooting-logs-only) · [Gotchas](#gotchas)

This reference covers custom solver script sections: `Simulation.set_scripts`, `CustomSection` hooks, the solver namespaces (`expr`, `par`, `reg`, `fld`, `qs`), generated scripts, the typed stubs (`quanscient/__init__.pyi`), and debugging from job logs.

Most workflows use SDK helpers (`create_simulation_*`, physics interactions, outputs) and **do not** need manual script edits. Read this reference only when adding custom script sections or fixing script failures.

**Custom scripts run on the Allsolve server** when `sim.run()` executes. They cannot be run or stepped through locally — there is no debugger attach, no local simulation runtime. Write and validate syntax locally; errors surface only in **cloud job logs** after a run.

**Docs:** Scripting (`/documentation/using-allsolve/simulations/scripting`) · Script API (`/documentation/reference/api`)

## Attach custom code

```python
sim.set_scripts([
    allsolve.Script(
        name="init_temp.py",
        section_name=allsolve.CustomSection.AFTER_FIELDS_CREATED,
        content="fld.T.setvalue(reg.all, expr.room_temp)",
    )
])
```

Provide code via `content` (inline string) or `filepath` (`.py` on disk, read at `set_scripts` time). Set `is_main=True` only to replace the entire generated main script.

`set_scripts` replaces the whole set: scripts not in the list are deleted. Pass every script in one call; read the current ones with `sim.get_scripts()`.

To replace a generated section, disable it. `start()`/`run()` save the change; call `sim.save()` before reading the setting back. `save_generated_scripts` never shows disabled sections commented out, nor your custom sections.

```python
sim.disabled_script_sections = [allsolve.DisableableSection.SOLVE]
sim.save()
print(sim.disabled_script_sections)  # check: [DisableableSection.SOLVE]
sim.set_scripts([...])               # the replacement code
```

Common injection points (`CustomSection`):

| Section | Typical use |
| ------- | ----------- |
| `AFTER_FIELDS_CREATED` | Initial field values, custom fields |
| `AFTER_CONSTRAINTS_CREATED` | Extra boundary conditions |
| `AFTER_FIELD_INITS` | Override generated initial conditions |
| `AFTER_FORMULATIONS_CREATED` | Modify weak form before solve |
| `BEFORE_TRANSIENT_SOLVE` | Per-timestep updates (transient only) |
| `AFTER_ALL` | Post-processing |

See `help(allsolve.CustomSection)` or SDK reference for the full list and analysis-type-specific sections.

## Solver environment vs SDK script

Custom scripts run **on the cloud solver**, not in your local SDK file. Python names from the SDK script (constants, function args, imports) are **not** in scope.

Autogenerated helper modules are injected at runtime:

| Symbol | Module | Use |
| ------ | ------ | --- |
| `expr.<name>` | `expressions` | Project variables and functions |
| `par.<name>()` | `parameters` | Material / interaction parameters per region |
| `reg.<name>` | `regions` | Region IDs |
| `fld.<name>` | fields namespace | Finite-element fields |
| `var.<name>` | generated script | Solver settings: `start_time`, `end_time`, `time_step`, `pml_num_layers` |
| `mesh`, `mat` | generated script | Mesh container (`mesh.mesh` is the `qs.mesh`); materials |
| `form` | generated script | The formulation (`qs.formulation()`), from `AFTER_FORMULATIONS_CREATED` on |
| `port.<namespace>.<q>` | generated script | Lump port quantities by the lump's `namespace` (`V`/`I`, `V`/`Q`, `T`/`Phi`, …; see physics-and-interactions.md) |
| `qs` | `quanscient` | Script API (`import quanscient as qs`) |

Names come from the project in snake_case, and interaction targets get a `_target` suffix (`reg.inlet_target`). A wrong name raises `AttributeError`. Read the generated `regions.py`, `parameters.py` and `expressions.py` for the exact names. `expr.<name>` entries are cached properties, read as `expr.x` (and assignable); `par.<name>()` and `mat.<material>.<prop>()` are methods, called with `()`.

```python
# Correct — project variable
content="fld.T.setvalue(reg.all, expr.room_temp)"

# Correct — runtime override of a project variable
content="expr.room_temp = qs.expression(273.15); fld.T.setvalue(reg.all, expr.room_temp)"  # replaces a number with an expression: code that uses expr.room_temp as a float breaks

# Also fine — bake a value when building Script content at SDK time
content=f"fld.T.setvalue(reg.all, {293.15})"

# Wrong — bare name not in solver namespace (NameError)
content="fld.T.setvalue(reg.all, room_temp)"
```

Project variables must be defined first: `project.create_variables([("room_temp", "293.15", ...), ...])`.

## Inspect generated scripts (reference only)

Fetch server-generated helpers to see exact `expr.*` / `par.*` names and aid local editing — **these files are not executed locally**:

```python
sim.save_generated_scripts("./generated_scripts/")
# writes utils.py, regions.py, expressions.py, parameters.py, materials.py, ...
```

Use with the typed stubs (`quanscient/__init__.pyi`) for IDE autocomplete while writing script strings. Refresh after changing project variables or regions.

- **The output folder must exist.** `save_generated_scripts` raises `ValueError: Given output_dir does not exist` otherwise; call `os.makedirs(path, exist_ok=True)` first.
- **The saved `simulation.py` is the plain generated script.** It does not show disabled sections or your custom sections, so it cannot confirm that they are in place. Check `sim.disabled_script_sections`, and read the job log of the run.
- It needs a valid project: the server generates the script, so an invalid interaction expression fails here with `simulation_script_generation_failed` before any run. This makes it a cheap check of a new model.

## Troubleshooting (logs only)

There is no interactive debugging. Workflow:

1. Edit script content in the SDK (or GUI script editor).
2. Run `sim.run(print_logs=True)`.
3. Read the job log — tracebacks, `NameError`, and syntax errors appear there before results upload.
4. Fix and re-run.

To inspect values on the server, use `print(...)` in the custom script section — output appears in the simulation logs under Results.

After changing project variables or regions, regenerated helpers update on the next run; call `save_generated_scripts` again if you need an updated local reference copy.

## Gotchas

### Formulation and timing

- **Sign convention:** all `integral()` terms are LHS (`sum = 0`). Negate known-value terms to move them to RHS.
- **Do NOT parse streamed logs for per-step timing** — the server batches lines. Use `time.perf_counter()` around `timestepper.allnext()` and emit via `qs.setoutputvalue`.

### Spatial material expressions (custom script)

- **Monkey-patching material properties** — to override stiffness with a spatially-varying expression, inject an `AFTER_IMPORTS` custom script snippet that replaces the material class's method before `par.H()` is constructed. Avoids the 5000-char expression limit.
- **Arbitrary spatial profiles from splines** — convert to solver expressions via piecewise cubic (`qs.ifpositive()` tree) or Fourier series (`qs.cos`/`qs.sin` sum). Do the fitting in Python during project setup.
- **Spatially-graded material from grid data** — `qs.grid(gridticks=[x,y], gridvalues=vals.flatten())` does linear interpolation; grid ticks should span the geometry (points outside clamp to nearest edge). For `(nely, nelx)` arrays, use `rho.T.flatten()` to match grid tick order.

### Harmonics and field access

- **Harmonic numbering:** 1=DC, 2=sin(wt), 3=cos(wt), 4=sin(2wt), 5=cos(2wt), … (`harm(2, x)` is the sine part).
- **For transient fields:** do NOT pass harmonic indices to `qs.field()`.
- **Gradient of harmonics:** always `qs.harm(n, qs.compx(qs.grad(field)), N)`, never `qs.grad(qs.harm(...))`.
- **`qs.norm()` for transient:** `qs.norm(fld.u)`. For harmonic: `qs.norm([2,3], fld.u, 3)`.
- **`qs.field("x")` returns metres**, not internal mm.
- **`qs.field("y")` for y-coordinate** — use `qs.field("y")`, not `qs.compy(qs.field("x"))`.

### Data structures

- **`densemat` is not a Python list** — use `dm.getvalue(i, 0)` to read elements.
- **`vec.setdata(reg, field)` reads field INTO vec**, not the other way.
- **`qs.evaluate()` may return list or scalar** — always unwrap: `float(v[0]) if isinstance(v, (list, tuple)) else float(v)`.

### Injection points

- **Custom sections are pasted into the generated script verbatim, at their position.** Nothing is re-indented, so write each section at the indentation of the place it goes to. In a transient, `BEFORE_TRANSIENT_SOLVE` (before each step's solve) and `AFTER_SOLVE` (after each step's solve) are inside the time loop: indent their code by 4 spaces. Code at column 0 there ends the loop and the job fails with `IndentationError`. In a harmonic simulation `AFTER_SOLVE` is inserted only when the simulation has outputs that are evaluated after the solve; otherwise it is dropped without an error. Put post-solve code in `AFTER_ALL`. `AFTER_IMPORTS`, `AFTER_FORMULATIONS_CREATED`, `AFTER_TIMESTEPPER_CREATED` and `AFTER_ALL` are at top level.
- **Disabling SOLVE comments out the solve code together with the custom sections inside it** (`AFTER_TIMESTEPPER_CREATED`, `BEFORE_TRANSIENT_SOLVE`, `AFTER_SOLVE`). `AFTER_FORMULATIONS_CREATED` and `AFTER_ALL` still run; either can hold a fully custom solve or time loop (template: `examples/pmut_surrogate/scripts/postprocessing.py`, which uses `AFTER_ALL`). To change only what happens in each step, keep SOLVE enabled and use the per-step sections instead.
- To see where your sections land, print the assembled script from an `AFTER_IMPORTS` section: `print(open('simulation.py').read())`. `save_generated_scripts` shows only the generated code, without your sections.
- **`qs.evaluate` cannot return a multiharmonic value** — extract a single harmonic first: `qs.evaluate(qs.harm(2, port.port.V))`.

### Predefined waves and PML

- **`predefinedacousticwave` no-PML overload:** use the 5-arg form, do NOT pass `None` as PML arg.
- **`numpy` and `scipy` are available** inside custom script sections. `quanscient` / `qs` is the solver module and is NOT importable locally.
